## 一、项目背景与业务机会

### 1.1 业务背景

笔记本电脑属于高信息密度、低频次购买的消费电子商品。消费者在购买前通常需要综合考虑预算、使用用途、性能、便携性、续航等多个因素，不同因素之间存在一定的制约关系。

当前电商平台主要通过商品搜索、分类筛选、排序及商品详情页帮助用户选购。这类方式能够高效定位符合明确参数要求的商品，但对于缺乏硬件知识、尚未确定具体型号的消费者，仍存在一定的决策门槛。

例如，用户知道自己需要一台“适合编程、偶尔剪视频、方便通勤”的电脑，却未必清楚这些需求对应怎样的配置，也难以判断不同商品之间的性能、重量和价格取舍。

现有选购方式主要存在以下潜在局限：

| 选购方式 | 主要能力 | 潜在局限 |
|---|---|---|
| 电商搜索与筛选 | 按价格、品牌、配置等条件查找商品 | 用户需要自行将用途转换为筛选条件 |
| 选购攻略与测评 | 提供参数知识、性能分析及购买建议 | 信息分散，需要核对具体商品配置及适用范围 |
| 通用 AI 问答 | 理解自然语言，提供选购知识和建议 | 缺少可信商品数据及校验机制时，可能产生不准确的推荐结论 |

### 1.2 业务机会

本项目拟在电商购买前决策环节引入 AI 导购能力，将传统的“用户主动搜索与筛选商品”拓展为“系统理解用户需求并辅助形成选购方案”。

核心机会在于：

- **降低选购门槛：** 让用户通过自然语言描述实际用途，而不必预先理解复杂的硬件参数。
- **提高信息整合效率：** 将商品信息、用途适配依据和候选差异整合为可理解的推荐建议。
- **改善购买前决策体验：** 帮助用户缩小候选范围，理解不同方案的优势与取舍。

从业务价值看，该能力有望提升选购服务的有效性，增强用户在商品决策环节的参与度，并为后续商品详情浏览和购买转化创造条件。

其中，选购任务完成质量是本期直接验证目标；用户参与度及购买转化改善属于后续需要验证的业务价值假设。

## 二、目标用户与核心需求

### 2.1 目标用户

本产品优先服务于：

**知道自身使用用途和大致预算，但缺乏专业硬件知识、尚未确定具体购买型号的消费者。**

目标用户具有以下典型特征：

- 能够描述日常使用任务、使用场景和个人偏好。
- 不熟悉硬件参数与实际使用能力之间的关系。
- 选购时需要在预算、性能、便携性等多个因素之间权衡。
- 希望获得少量有依据的候选商品，而非自行比较大量配置。

不以已确定具体型号、仅查询价格或库存的用户，以及能够独立完成专业配置评估的用户作为 V1.0 核心服务对象。

### 2.2 核心需求

围绕购买前决策，本项目重点解决三个问题。

**需求一：将自然语言需求转化为可用于选购的有效信息。**

用户能够表达“每天通勤”“偶尔剪视频”“希望续航好”等实际需求，但不一定能够自行确定相应的硬件要求。

产品需要理解用户的用途、硬条件和软偏好，并识别真正影响推荐判断的信息缺口。

**需求二：判断具体商品能否满足实际使用任务。**

用户不仅需要知道商品的处理器、内存、重量等参数，还需要理解这些参数与自身使用任务之间的关系。

产品需要基于可核对的商品事实和用途适配依据形成判断，而不是仅依据参数名称或模型常识进行推荐。

**需求三：理解多项要求之间的取舍。**

在预算、性能和便携性等因素无法同时达到理想状态时，用户需要理解不同候选的优势、不足，以及这些差异对自身使用场景的影响。

产品应提供可解释的候选方案，辅助用户自主作出选择，而不是强制给出唯一最佳商品。

## 三、产品定位与差异化价值

### 3.1 产品定位

**笔记本电脑 AI 导购 Agent 是面向购买前决策的智能选购助手，通过理解用户自然语言需求，动态获取必要信息，形成可信的商品候选，并解释不同方案之间的取舍。**

产品以用户实际用途为中心，在已接入的商品数据及适配依据范围内，提供从需求理解到候选形成、比较及条件调整的连续选购服务。

产品提供购买决策参考，不代替用户完成最终购买决定，也不承诺推荐全市场最优商品。

### 3.2 核心价值主张

**让用户不必先掌握复杂硬件参数，也能获得符合自身需求、依据可核对、取舍可理解的笔记本电脑选购建议。**

产品价值体现在三个层面：

1. **需求理解：** 将用户日常语言中的用途、约束和偏好转化为结构化、可核对的选购信息。
2. **可信推荐：** 基于具体商品事实与用途适配依据形成候选，降低无依据推荐的风险。
3. **决策辅助：** 将商品参数差异解释为与用户需求相关的实际取舍，降低比较和理解成本。

### 3.3 差异化方向

相较于传统商品筛选和一次性 AI 问答，本产品重点建立三项差异化能力：

| 差异化能力 | 产品价值 |
|---|---|
| 动态需求澄清 | 根据当前选购判断的信息缺口进行必要提问，避免用户预先填写大量参数 |
| 基于证据的推荐 | 结合商品事实与用途适配依据，区分确定结论、使用限制和未知信息 |
| 连续选购决策 | 用户调整条件后，重新评估受影响的候选和理由，支持持续比较与取舍 |

差异化的关键不在于提供对话界面，而在于系统是否能够根据用户需求和实际信息状态，采取有价值的后续行动，并形成可靠的决策辅助结果。

## 四、AI/Agent 方案选择与价值论证

### 4.1 AI 能力适用性

笔记本电脑选购涉及自然语言理解、信息检索、用途适配判断和推荐解释等不同类型的任务。

其中，用户需求表达形式多样，存在歧义、缺失及动态变化；商品筛选与配置检查则需要遵守明确的业务约束。

因此，本项目采用 **LLM 与确定性业务规则协同** 的方案：

- 大语言模型负责语义理解、信息缺口识别、行动选择与自然语言解释。
- 业务工具负责获取商品事实与适配依据。
- 确定性规则负责硬条件过滤、可规则化的适配检查及结果校验。

通过职责分离，发挥模型处理非结构化需求的能力，同时降低模型直接生成商品事实和业务结论带来的风险。

### 4.2 方案比较与选择

针对核心选购任务，主要考虑以下三类方案：

| 方案 | 优势 | 主要局限 |
|---|---|---|
| 传统规则推荐 | 执行稳定、成本可控、结果可预测 | 依赖结构化条件，难以直接理解复杂自然语言需求 |
| LLM + 固定工作流 | 能够理解自然语言，执行路径清晰，易于控制 | 面对不同信息缺口时，任务推进顺序和处理策略相对固定 |
| 受约束的 Agent | 能够根据当前状态和中间结果，动态选择澄清、检索、核验等行动 | 决策路径更复杂，需要额外控制可靠性、执行成本和响应时间 |

对于需求明确、商品信息充分的简单选购任务，固定工作流可能已经足够。

但当用户需求不完整、商品证据存在不确定性，或条件变化导致部分判断失效时，系统下一步应执行什么操作，可能需要根据中间结果重新判断。

基于这一特点，V1.0 选择**受约束的单 Agent 方案**，重点验证其在复杂选购场景中的动态任务决策能力与推荐可靠性。

### 4.3 Agent 的核心价值

Agent 的自主性主要体现在**任务推进与行动选择**，而非不受限制地生成推荐结果。

例如：

- 当前信息足够时，直接推进商品查询及推荐判断。
- 发现关键用户需求缺失时，判断是否需要澄清。
- 商品信息或适配依据不足时，判断能否进一步获取有效证据。
- 无可靠候选时，识别问题原因，提供符合实际约束的后续操作。
- 用户修改条件后，判断哪些已有信息仍然有效，避免不必要的重复处理。

上述行动由当前任务状态和中间结果共同决定，不要求所有任务遵循完全相同的固定执行路径。

### 4.4 方案边界与价值验证

Agent 的行动必须受到业务规则约束：

- 不擅自改变或放宽用户已确认的硬条件。
- 不将软偏好直接转换为未经确认的硬性限制。
- 不编造商品事实、用途适配依据或实际使用体验。
- 不绕过硬条件过滤及推荐结果校验。
- 信息不足时允许停止并说明原因，不强行形成推荐。

本项目重点验证 Agent 在实际选购任务中的**决策有效性、推荐可靠性及执行可控性**。

验证重点包括：

- Agent 能否根据不同的需求和信息状态，选择合理的下一步行动。
- 能否识别影响推荐判断的关键需求缺口，并在必要时发起澄清。
- 能否合理使用已有商品事实与适配依据，避免无效或重复的信息获取。
- 能否在条件冲突、证据不足或无可靠候选时作出正确处理。
- 能否在可接受的响应时间和执行成本内完成选购任务。

Agent 的具体状态、行动空间、决策规则、执行循环和约束机制将在独立的 Agent Harness 设计文档中定义。

## 五、MVP 版本目标与产品边界

### 5.1 V1.0 版本目标

V1.0 聚焦笔记本电脑购买前选购，建立从自然语言需求输入到可信候选推荐的完整业务闭环。

本期重点验证：

- 用户能否通过自然语言完成选购需求表达。
- 系统能否基于可信商品事实和适配依据形成有效候选。
- Agent 能否根据不同信息状态合理选择后续行动。
- 用户能否理解推荐理由、商品不足及候选之间的取舍。
- 条件变化或无法推荐时，系统能否保持一致且可靠的处理结果。

### 5.2 数据与能力边界

V1.0 使用预先整理、来源可追溯的笔记本电脑商品目录和用途适配依据。

选择有限商品数据范围，主要基于以下产品考虑：

- 控制商品事实和适配依据的质量，保证推荐结果可核对。
- 降低外部信息变化对核心任务验证的干扰。
- 优先验证选购决策能力，而不是商品覆盖规模。

本期不包含：

- 实时全网商品搜索与比价。
- 下单、支付、订单管理和售后。
- 跨品类商品导购。
- 多 Agent 协作。
- 用户长期记忆与复杂个性化推荐。

商品目录内的价格、库存等信息应明确数据来源与更新时间；非实时或模拟数据不得表述为实时信息。

## 六、成功标准与关键风险

### 6.1 业务目标

本期从三个维度评估产品价值。

**目标一：选购任务有效完成**

用户能够在系统辅助下获得满足已确认条件、具备用途适配依据的商品候选；无法推荐时，能够了解准确原因及可继续的路径。

**目标二：推荐结果可信且可理解**

推荐中的商品事实与来源记录一致，关键用途判断有依据，用户能够理解候选优势、不足及取舍。

**目标三：Agent 动态决策有效且可控**

在复杂选购任务中，Agent 能够根据当前需求和中间结果合理选择下一步行动，避免不必要的澄清与工具调用，并将响应时间和执行成本控制在合理范围内。

### 6.2 核心成功指标

| 指标 | 衡量目标 |
|---|---|
| 有效选购任务完成率 | 衡量可完成任务中成功形成可靠候选的比例 |
| 硬条件违反率 | 衡量正式推荐结果是否违反用户已确认的硬条件 |
| 商品事实准确率 | 衡量推荐中的关键商品事实是否与来源记录一致 |
| 推荐解释可理解性 | 衡量用户能否理解推荐依据、主要不足及取舍 |
| Agent 行动决策合理率 | 衡量 Agent 在不同状态下选择行动的合理程度 |
| 单任务执行效率 | 衡量任务耗时、澄清轮次、工具调用次数及模型成本 |

本期以**有效选购任务完成率**作为核心结果指标，以硬条件遵守和商品事实准确性作为关键质量约束。

对于明确违反硬条件、编造关键商品事实等严重问题，应设置独立的验收阻断标准，不以其他指标的良好表现抵消。

具体统计口径、目标阈值和测试样本将在 Evaluation 文档中确定。

### 6.3 关键风险与应对方向

| 关键风险 | 应对方向 |
|---|---|
| 商品数据与适配依据不足 | 明确数据边界，缺少有效证据时不生成确定结论 |
| LLM 误解用户需求或编造事实 | 区分硬条件与软偏好，通过用户核对和确定性规则控制关键结果 |
| Agent 行动不合理、成本不可控 | 限制行动范围和执行预算，记录决策轨迹并开展评估 |
| 推荐结果对用户决策帮助有限 | 通过目标用户测试，验证推荐依据、候选差异和取舍解释的实际可理解性与使用价值 |

### 6.4 阶段性决策标准

V1.0 的验证结果将用于判断：

1. 产品是否能够可靠完成目标用户的核心选购任务。
2. 可信推荐和取舍解释是否产生可感知的用户价值。
3. Agent 能否稳定作出合理行动决策，并将执行成本控制在可接受范围内。
4. 当前商品数据、适配依据与产品能力是否支持继续扩大服务范围。

未完成验证的价值判断不作为已经实现的业务成果。

---

## 项目定义结论

V1.0 以笔记本电脑购买前选购为切入场景，以**可信候选推荐与可解释决策辅助**为核心产品价值，采用受约束的单 Agent 方案处理复杂需求和动态信息获取任务。

本期优先验证选购任务完成质量、推荐可靠性、用户对选购建议的理解程度，以及 Agent 动态决策的有效性与可控性，为后续功能迭代、数据扩展和业务投入提供依据。
