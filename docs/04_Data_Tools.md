# 04 数据与工具

> 状态：初始接口草案；JSON Schema 与数据来源待补充。

## 数据原则
商品参数与用途适配依据分开管理。每条事实保留来源、采集时间和适用条件；缺失值明确标记为未知。模拟数据不得作为真实选购依据。

## 拟定商品字段
product_id、品牌型号、价格及时间、CPU、GPU、内存、存储、屏幕、重量、来源。
具体单位、枚举与必填项待定；同型号不同配置须能区分。

## 拟定适配规则字段
rule_id、用途、任务强度、适用条件、必要配置、解释、来源、版本。
阈值必须有依据，不能由模型随意生成。

## 工具契约
| 工具 | 输入概要 | 输出概要 |
| --- | --- | --- |
| search_products | 已明确条件与条件版本 | 商品 ID、概要、匹配数量 |
| get_product_details | 商品 ID 列表 | 配置事实、未知项与来源 |
| retrieve_fit_evidence | 用途及任务参数 | 适配依据、适用范围与缺失项 |

统一返回成功/失败状态；失败含错误类型与可重试标记。无匹配是成功查询的空结果。
仅当信息确实需要按需获取时拆分工具，避免人为增加调用。

## 确定性规则
src/rules/ 实现硬条件过滤、适配规则执行与最终推荐校验。校验结果区分满足、不满足和未知。
推荐引用的商品 ID 与证据 ID 必须存在，且适用于当前条件版本。
