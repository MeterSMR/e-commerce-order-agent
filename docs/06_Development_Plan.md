# 06 研发交付计划

> 当前进度：Project Brief v1.1 已完成内容编写，仍标记为待评审；其余需求与设计文档为模板或草案。仓库已初始化目录，应用、数据与测试尚未实现。下列安排为阶段计划。

| 阶段 | 交付内容 | 验收方式 |
| --- | --- | --- |
| 1 需求与方案 | 完成 PRD，再完善 Harness、数据工具和评测方案 | 核心场景、产品行为、版本边界与验收条件一致；实现所需决策明确 |
| 2 UI 与交互 | 搭建应用、对话框、条件卡、商品卡与比较页 | 本地启动，使用标记为模拟的数据检查已确认交互 |
| 3 数据与业务能力 | 商品目录、用途适配依据、工具及确定性校验 | 验证来源可追溯、边界值、缺失数据、不满足条件及工具异常 |
| 4 Harness | 模型调用、行动选择、状态、循环、暂停恢复 | 验证不同信息状态产生合理路径，条件变化后正确失效与复用 |
| 5 用户闭环 | 推荐、追问、比较、改条件与异常反馈 | 端到端运行 PRD 核心场景 |
| 6 评测与交付验证 | Agent 能力评测、用户理解测试、Trace、问题修复记录与演示 | 按已确认验收标准输出实际结果和可复现启动说明 |

## 实施约定

- 先明确影响当前阶段的需求和设计决策，再拆分为可验证的小任务；不将草案参数视为已确认要求。
- PRD 定义用户可感知的产品行为；Harness 定义 Agent 机制；数据工具文档定义数据与接口；评测文档定义验证方法与标准。
- 实际安装时核验技术框架和版本，将依赖锁文件加入 Git。
- 每阶段更新 README 的能力状态与可用启动方式，真实记录测试是否执行。
- 研发记录归档至 evidence/development-log.md 或 evidence/development/；实测结果归档至 evidence/evaluations/。
- 后续文档完成或需求变更时，同步更新受影响的设计、实现与验收项。
