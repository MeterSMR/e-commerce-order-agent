# 03 Agent Harness 设计

> 状态：设计骨架；字段类型、参数上限和接口需进一步确定。

## 目标与权限
Agent 根据用户需求与已有证据选择下一步行动。不得编造商品事实、适配规则或自行放宽硬条件。

## 状态
| 状态项 | 内容 |
| --- | --- |
| requirements | 用户硬条件、偏好、用途及未明确项 |
| requirement_version | 条件版本，防止复用过时结论 |
| candidates | 检索候选及商品标识 |
| evidence | 已获取依据、来源和适用范围 |
| validations | 硬条件与适配校验结果 |
| execution | 步数、澄清次数、失败次数与已执行行动 |
| status | running / waiting_user / completed / stopped / failed |

## 行动空间
ask_user、search_products、get_product_details、retrieve_fit_evidence、recommend、stop。
其中 ask_user、recommend、stop 是控制行动，具体接口在数据工具文档中定义。

## 决策原则
- 有足够条件可先查询，缺少会影响判断的信息时再澄清。
- 商品事实缺失时读取详情；用途依据不足时检索证据。
- 不重复执行输入和信息状态都未改变的无效操作。
- 证据无法补齐时说明限制，不猜测关键事实。
- 行动决策可变，但推荐资格必须由程序强制校验。

## 执行循环
读取状态 → LLM 选择行动 → 程序校验权限和参数 → 执行 → 更新状态 → 判断是否继续。
询问用户时保存状态并暂停；收到回答后更新状态并恢复。
推荐前运行确定性校验；未通过时不可输出为合格推荐。

## 约束与终止
- 待确认：每次任务的步数、工具重试次数、超时与成本上限。
- 澄清上限建议为两轮，需在评估中验证。
- 达到上限时说明限制；无匹配时提出可选择的调整，不自动更改硬条件。
- 条件修改后更新版本，使受影响的候选和校验结果失效。

## Trace
记录行动名称、简短决策依据、输入摘要、工具结果摘要、校验状态、耗时与终止原因。
不记录隐藏思维链、真实密钥或不必要的个人信息。
