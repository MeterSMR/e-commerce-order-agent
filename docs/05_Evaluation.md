# 05 评估与验收

> 状态：评测方案草案，尚未执行测试，无实测指标；统计口径、样本与验收阈值待结合 PRD 和 Harness 细化。

## 评测目标与指标方向

依据 Project Brief，验证 Agent 的选购任务完成质量、推荐可靠性、决策有效性及执行可控性。本期不开展 Agent 与固定工作流的效果对照实验。

| 评测维度 | 指标或检查重点 |
| --- | --- |
| 任务完成质量 | 有效选购任务完成率；无法推荐时是否准确解释原因并提供可继续的路径 |
| 推荐可靠性 | 硬条件违反率、商品事实准确率、事实可追溯性与适配证据适用性 |
| Agent 决策质量 | 行动决策合理率；能否识别关键缺口、适时澄清、补充证据或停止 |
| 推荐解释可理解性 | 用户能否理解推荐依据、主要不足及候选之间的取舍 |
| 单任务执行效率 | 响应耗时、澄清轮次、工具调用次数、无效或重复调用情况、模型成本 |

以有效选购任务完成率作为核心结果指标。明确违反硬条件、编造关键商品事实等严重问题应作为独立验收阻断项，不以其他指标的良好表现抵消；具体判定规则在完整评测方案中确定。

## 初始场景

| 场景 | 验收重点 |
| --- | --- |
| 信息充分 | 能直接推进检索、校验与推荐，不强制澄清 |
| 用途不明确 | 询问会影响候选或适配结论的问题，避免重复询问 |
| 商品参数缺失 | 获取详情或明确未知，不编造 |
| 无匹配商品 | 说明无匹配原因；存在条件冲突时解释冲突，不自动放宽硬条件 |
| 证据无法补齐 | 限定结论或停止推荐，不把未知当作满足 |
| 查询失败 | 区分失败与空结果，按上限重试或停止 |
| 用户修改预算或其他条件 | 重新验证受影响的候选资格与结论，复用仍有效的事实和证据；不沿用失效推荐 |
| 循环重复或超限 | 及时终止并解释限制 |
| 单款追问与比较 | 结论与商品事实一致，明确差异、限制及未知项 |
| 推荐解释理解 | 通过目标用户测试检查用户能否理解推荐理由、不足与取舍 |

## Agent 决策评测方法

- 为同类需求设置不同的信息完整度、证据状态与工具结果，检查行动是否符合当前任务状态及业务约束。
- 允许多条合理行动路径，不把唯一工具顺序当作正确答案；具体允许行动和失败条件随 Harness 设计细化。
- 条件调整场景同时检查失效结论的重新验证和有效信息的复用，识别遗漏校验及无效重复调用。
- 记录输入、数据与规则版本、模型与 Prompt 版本、执行配置、行动轨迹、输出和判定依据；重复运行次数待确定。
- 正常完成、无可靠候选、证据不足和工具失败分开记录，避免将无法完成的任务混入可完成任务的完成率分母。
- 通过目标用户测试验证解释可理解性；不以模型自评替代用户理解结果。

## 测试分层

- tests/rules/：确定性规则。
- tests/agent/：模拟工具结果下的状态与行动边界。
- tests/e2e/：真实应用用户闭环。
- 真实模型评测、模拟测试与目标用户测试分开记录，结果归档至 evidence/evaluations/。
