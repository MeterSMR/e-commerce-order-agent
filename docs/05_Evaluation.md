# 05 评估与验收

> 状态：评估计划，尚未执行测试，无实测指标。

## 评估维度
- 推荐可靠性：硬条件遵守、事实可追溯、证据适用性。
- 澄清有效性：问题是否影响结果、是否重复。
- 执行效率：无效调用、总调用数、耗时与成本。
- 用户闭环：追问、对比、改条件、异常反馈是否完成。

## 初始场景
| 场景 | 验收重点 |
| --- | --- |
| 信息充分 | 能直接检索、校验并推荐，不强制澄清 |
| 用途不明确 | 询问会影响适配结论的问题 |
| 商品参数缺失 | 获取详情或明确未知，不编造 |
| 无匹配商品 | 解释冲突，不自动放宽硬条件 |
| 证据无法补齐 | 限定结论或停止推荐 |
| 查询失败 | 区分失败与空结果，按上限重试 |
| 用户修改预算 | 旧结果失效，重新验证 |
| 循环重复或超限 | 及时终止并解释限制 |
| 单款追问与比较 | 结论与商品事实一致 |

## 对照实验
固定工作流与 Agent 使用相同模型、数据、工具、业务规则和任务预算。
对同一需求提供不同信息或证据状态，比较可靠性、澄清次数、工具调用数、耗时和成本。
允许多条合理行动路径，不把唯一工具顺序当作正确答案。
重复运行并记录模型与数据版本；不预设 Agent 一定优于工作流。

## 测试分层
- tests/rules/：确定性规则。
- tests/agent/：模拟工具结果下的状态与行动边界。
- tests/e2e/：真实应用用户闭环。
- 真实模型评估与模拟测试分开记录。
